Next.js 16 Metadata API references:
- `metadataBase: URL` — resolves relative OG/Twitter image paths to absolute URLs
- `title: { default, template }` — template applies to child route titles that pass a plain string
- `themeColor` — must be set via `viewport` export in Next 16 (NOT inside `metadata`). Verify against installed `next` version before placing.
- `twitter.images` and `openGraph.images` accept relative paths; metadataBase resolves them.
- File convention `app/opengraph-image.tsx` is auto-detected — referencing `/opengraph-image` in images is optional but explicit; preferred for determinism.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → static HTML | Untrusted client renders metadata in `<head>`; SSG output only. No runtime input crosses. |
| build → env vars | `NEXT_PUBLIC_SITE_URL` baked into client bundle at build time; public by definition. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Information disclosure | NEXT_PUBLIC_SITE_URL | accept | Public site URL; leakage is intended. No secret material in env. |
| T-04-02 | Spoofing | Open Graph image URL | mitigate | metadataBase + literal fallback ensure OG image URL resolves to the canonical domain even if env var unset; prevents accidental relative-path resolution on a hijacked subdomain. |
| T-04-03 | Tampering | Page metadata | accept | Metadata is build-time static; no runtime mutation path. |
</threat_model>
