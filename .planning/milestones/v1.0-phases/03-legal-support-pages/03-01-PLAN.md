Tailwind v4 plugin registration:
- Tailwind v4 does NOT use a `tailwind.config.js`. Plugins are registered inside the CSS file itself via the `@plugin` directive.
- Syntax: `@plugin "@tailwindcss/typography";` placed at the TOP of `app/globals.css`, after the existing `@import "tailwindcss";` line and BEFORE any other `@import` (so the plugin's utilities are available when downstream layers compile).
- Reference: Tailwind v4 docs — `@plugin` directive replaces the legacy `plugins: [...]` config-file array.

Package install:
- Use `npm install -D @tailwindcss/typography` — adds to `devDependencies` (the plugin is a build-time dependency only).
- The installed version should satisfy `^0.5.x` (current stable). Do NOT pin a specific patch; let npm resolve the caret range.

Existing globals.css structure (DO NOT remove or reorder):
- Line 1: `@import "tailwindcss";` — the Tailwind v4 entry point. Keep at top.
- Line 2: `@import "tw-animate-css";` — animation utility package (Phase 2 carryover).
- Line 3: `@import "shadcn/tailwind.css";` — shadcn base styles.
- Insert the new `@plugin "@tailwindcss/typography";` directive AFTER `@import "tailwindcss";` and BEFORE `@import "tw-animate-css";` so the plugin attaches to the v4 engine that was just imported.

Wave 2 consumer pattern (FYI — implemented in Plans 03-02/03/04):
- Legal pages will render an `<article>` with className including `prose prose-headings:text-emerald-600 prose-headings:font-semibold prose-p:text-navy-800 prose-a:text-gold-500 prose-a:no-underline hover:prose-a:underline prose-a:underline-offset-4 max-w-3xl mx-auto px-screen py-section`. The `prose-*` utility variants are the per-element overrides D-27 calls out; they only resolve to real styles when this plugin is registered.
- DO NOT pre-create any of those overrides in this plan — Plans 03-02/03/04 apply them inline at their respective use sites.
